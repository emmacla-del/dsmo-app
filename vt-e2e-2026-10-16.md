## Defects (most severe first)

### 1. P1 · export (official PDF) — 8.8 roster prints every man as sex 2 (woman), and blank rows print "2 / 2"
- Steps: in 8.8, enter a man (Sexe = Homme) and a woman, then open the PDF review copy (or the official PDF).
- Expected: Sexe 1 for the man. Empty roster rows stay empty.
- Actual: the man's row prints Sexe **2**. Rows 3–14 (empty) print Sexe **2** and Admin **2 (Non)**.
- Cause: the wizard stores sex as the code `"1"`/`"2"` (stored data: `s8q8_row2_sex:"1"`). `vtSexKey` only recognises M/F words, returns '' and the template falls to its else branch.
  - `src/services/pdf-data-mapper.service.ts:1604-1611` (vtSexKey), `:2024` (sexe), `:2026` (personnelAdministratif false for blank rows)
  - `src/pdf/templates/dynamic/vocationalTraining.hbs:1665` (`{{#if (eq sexe 'M')}}1{{else}}2{{/if}}`), `:1667` (same pattern for Admin)
- The 8.8 roster export is correct (sex 1/2, isAdminPersonnel 0/1). Only the PDF is wrong. Official PDF output, so §21 approval is needed.

### 2. P1 · FE — a commune (1.7) the respondent typed is silently replaced by the arrondissement name after a reload
- Steps: open the wizard for a new centre (1.6 is prefilled "Douala 2" and 1.7 is **empty**, so it was not auto-filled on the first visit). Type "Douala 2e" in 1.7 and continue. The server draft has `VT1_7:"Douala 2e"`. Reload the page and continue to the review.
- Expected: 1.7 = "Douala 2e" (owner rule 2026-10-12: a typed commune is never replaced).
- Actual: review, PDF, admin file and export all show 1.7 = "Douala 2" (`rawData.VT1_7:"Douala 2"`). On the first visit the autofill did not happen at all.
- Cause: `useVtDerivedCommune` keeps the last arrondissement in a ref that is `undefined` on mount. It cannot tell a typed commune from a derived one, and its effect fires as the prefill and draft data arrive, so the result depends on the order they load in. `react-web/src/lib/use-vt-derived-commune.ts:18-26, 39-49`.

### 3. P1 · export / data protection — the "anonymous" statistical dataset carries named personal data

- Expected: per `canonical-exclusions.ts` ("prevent exposure of personally identifiable information in anonymized research datasets"), no names, phones or emails.
- Actual: the row for 60b107b8 has `VT1_15_NAME`, `VT1_15_TEL1`, `VT1_15_EMAIL`, `VT1_16_NAME` (promoter), `VT1_16_TEL1`, `VT1_16_EMAIL` and `VT2_12` (centre email). The .sav also contains the respondent's name. Labels in the .sps: `VT1_15_NAME '1.15 — Noms et prénoms'`.
- Cause: only `VT8_8` is excluded. `src/data-management/canonical-exclusions.ts:15-28`.
- Needs a data-protection decision (export semantics, §21): exclude these fields, or move them to a restricted contact file like 8.8. Also check which roles may download the main dataset (regional and divisional?).

### 4. P2 · FE / export — "Add a specialty" / "Add a row" drops row 1 when row 1 is empty
- Steps: on 4.5, 4.6 (or any progressive grid, and the 8.8 roster), click "Add a specialty" before typing in the first line.
- Expected: a second line appears under line 1.
- Actual: line 1 disappears and a single line (slot 2) is shown, so the first click seems to do nothing. Data is then stored from `row2` (`s4q5_row2…row4`, `s4q6_row2…row4`). Knock-on effects:
  - the PDF prints an empty line 1 before the data (4.5)
  - the export has `s4q5_row1_*` blank with data in rows 2–4
  - in the 8.8 roster, a second Add re-opens slot 1 *above* slot 2, and values typed into the expected slot 3 were lost
- Cause: `react-web/src/components/onefop/tables/VtProgressiveRowGrid.tsx:160-177`. The empty table shows slot 0 only through `shownSet.add(0)`. `next` is computed with 0 already in the set, so `add()` opens slot 1, and once `opened` is non-empty slot 0 is no longer shown. `VtRosterGrid.tsx` behaves the same way.

### 7. P2 · FE — "Saved just now" is shown after a local (IndexedDB) write only

- Cause: the toast is driven by `draftStatus` of the local buffer: `react-web/src/app/onefop/preview/page.tsx:349` → `react-web/src/components/onefop/WizardShell.tsx:295-303, 1153-1179`. This contradicts the comment in `use-onefop-server-save.ts` (never call the local copy saved).

### 8. P2 · FE (auth) — admin shell keeps running with no token: "Officer account", "Unauthorized" panels, continuous polling
