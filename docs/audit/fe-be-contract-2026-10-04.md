# FE-BE contract check — 2026-10-04

Read-only audit. No source file was modified and no tests were run.

## Method and scope

**Scope actually covered:** 76 routes from the FE call-site sweep. Three of the paths in the brief turned out not to be API endpoints at all (`/admin/notifications`, `/admin/sectors`, `GET /auth/users/:id`), and `PUT /campaigns/:id` exists on the backend with no FE caller. Verb correction worth noting up front: 11 routes the brief listed as POST are `@Patch` on the backend — the FE sends PATCH on all 11, so there's no drift there.

**No CRITICAL findings.** Nothing in the admin surface reads a field off an `undefined` parent or JSON-parses a binary body. The two HIGHs are both silently-wrong-UI.

I've bundled pure "BE returns a field the FE type omits" findings into one row per endpoint rather than one row per field — otherwise the LOW section runs to ~90 rows of payload-weight noise.

**Not API endpoints** (brief listed them as such): `/admin/notifications` and `/admin/sectors` are Next.js page routes; `GET /auth/users/:id` has no handler and no caller (`auth.controller.ts:398-402` documents the omission deliberately, which is why `users/search` is registered before the `:id` block).

Scope note: Groups D and E were told the data-integrity findings already in `docs/audit/endpoint-integrity-2026-10-04.md` were covered, so nothing above re-examines the fabricated-zero / territory-scoping issues on the pilotage and stats endpoints. Those remain open separately.

## Binary exports

**Binary exports are clean** — all three file routes go through `downloadExportBlob` (`api-client.ts:712-763`), which uses a bare `fetch` + `res.blob()` and attempts `res.json()` only on the `!res.ok` path (`:741`). Backend sets matching `Content-Type` + `Content-Disposition` on each (`data-management.service.ts:1469-1470`, `:753-754`, `:924-926`).

## Top 3 risks

1. **`companyName` on the Pilotage dashboard (#1)** — the "Activité Récente" panel is the first thing a regional or central admin sees, and every row reads `Fiche #a3f91c20` instead of the establishment name. The data is in the payload; the FE just reads the wrong key, and both its fallbacks are also wrong keys. Highest blast radius of anything here because it degrades the primary admin landing surface for every user, silently, with no error.

2. **Dateless ONEFOP declaration history (#2)** — a respondent opening their declaration history sees no submission date on any ONEFOP row, while DSMO rows show theirs correctly. For a statistical declaration portal where "did my Q3 return go in, and when" is the whole question the page answers, a blank date column undermines the respondent's ability to confirm their own compliance — and the inconsistency with DSMO rows makes it read as data loss rather than a display bug.

3. **`isOpen` hardcoded `true` on `/onefop/active-quarter` (#3)** — the backend never reports a closed collection period, so the wizard and submission panel will accept and submit a declaration against a round whose `status` or `deadline` has passed. That is the one finding here that can put a wrongly-attributed row into the statistical record rather than merely mis-render one, and it also means four FE closed-period branches have never executed in production.

## Near-misses worth naming

Two near-misses worth naming since they're one code change from biting: `PATCH /auth/reject-user/:id` (#17) guarantees a server 400 whenever an admin rejects from `UsersDirectory` without typing a reason, because that modal — unlike the other two call sites — doesn't gate on it; and `verifiedBy` (#16) would render a raw UUID to an admin the moment anyone uses the PATCH response instead of refetching.

## Deferred to fix branches

Everything at LOW severity — rows 25–90 — is deferred. None of it produces wrong
data on a reachable path today; each is either payload weight, a defensive
over-declaration, or a drift whose consumer already compensates. Grouped into
disjoint buckets so a branch can take one bucket at a time. Row numbers refer to
the merged findings table above.

- **Unused BE fields (payload weight only)** — 37, 44, 48, 49, 51, 53, 56, 57,
  61, 63, 64, 71, 75, 77, 87, 88, 89. The BE returns fields no FE type declares.
  Mostly raw Prisma rows served without a `select`.
- **Phantom or dead FE fields whose fallbacks already work** — 25, 26, 34, 35,
  36, 39, 43, 74, 84. The FE declares a field the BE never sends, but the read
  is a `??` chain that lands on a correct value. Fixing these removes dead

- **Over-nullable or over-wide FE declarations (defensive only)** — 31, 52, 59,
  60, 65, 66, 76, 78, 81, 86. FE types a field `T | null` or optional where the
  column is NOT NULL, or keeps a `Date` arm that JSON can never deliver. The
  null branches are unreachable.
- **Enum and union drift** — 30, 33, 46, 50, 54, 82, 85. FE union sets that are
  wider or narrower than the backing Prisma enum. No invalid value can currently
  be produced or sent, but a new enum member would not be type-caught.
- **Request-direction drift no caller exercises** — 40, 47, 55, 58, 68. Fields
  declared and never sent, or sent and silently stripped. Worth noting that 68
  means campaign targeting always defaults to all regions / all entity types.
- **Missing or inert request validation** — 32, 42, 69, 80, 83, 90. Routes with
  `@Body() data: any`, a bare TS interface as the body type, or an unvalidated
  `@Query`. Bad input surfaces as a Prisma 500 rather than a 400 with a
  `{ message }` envelope, which degrades `ApiError.message` to `res.statusText`.
  The FE guards every one of these today.
- **Untyped FE responses** — 27, 45, 73. `apiFetch` with no generic, or
  `items: any[]`. No drift is detectable at the wrapper; these were verified
  against page-level mappers instead.
- **Shape drift on an unreachable branch** — 62, 67, 72. Real array-vs-envelope
  and optional-vs-absent mismatches that no current call path reaches.
- **Value or semantics drift with no current reader** — 28, 29, 38.
- **Routes with no counterpart** — 70 (`PUT /campaigns/:id`, backend only),
  79 (`GET /onefop/draft`, backend only).
- **Type reuse across routes that cannot produce the fields** — 41. `DirectoryUser`
