## 2. Per-Defect Resolution (Defects 1–10)

### Defect 1 — P1 · Official PDF: 8.8 roster sex rendering & empty row defaults
- **Status:** Fixed (`6bf65bcc`)
- **Cause:** Confirmed. The form wizard stores sex as numeric string codes (`"1"` for Male, `"2"` for Female). `vtSexKey` only matched strings `"M"`, `"F"`, `"HOMME"`, `"FEMME"`, returning empty string for `"1"` and `"2"`. In `vocationalTraining.hbs`, `{{#if (eq sexe 'M')}}1{{else}}2{{/if}}` defaulted any non-`'M'` value (including empty string on blank roster rows) to `2`, producing `"2 / 2"` on empty rows 3–14.
- **Changes:**
  - `src/services/pdf-data-mapper.service.ts:1604-1616`: Added `'1'` to male matches and `'2'` to female matches in `vtSexKey`.
  - `src/pdf/templates/dynamic/vocationalTraining.hbs:1665, 1667`: Replaced fallback `else` branches with explicit checks so empty/missing values render blank (`{{#if (eq sexe 'M')}}1{{else if (eq sexe 'F')}}2{{/if}}`, and administrative personnel `{{#if (eq personnelAdministratif true)}}1{{else if (eq personnelAdministratif false)}}2{{/if}}`).
- **Tests & Result:**
  - Added unit test in `src/services/pdf-flow.spec.ts:318-360` verifying roster rendering with a man (`"1"`), a woman (`"2"`), and empty rows. Asserted: male renders 1, female renders 2, empty rows render empty. Passed (17/17 passed in suite).
- **Findings Missed by Source Report:** Audited Handlebars templates across other entities (`administration.hbs`, `enterprise.hbs`) for `{{else}}` defaults on binary fields; those templates check boolean presence properly.

- **Status:** Fixed (`818d8eef`)
- **Cause:** Confirmed. In `VtProgressiveRowGrid.tsx:160-177` and `VtRosterGrid.tsx:145-162`, an empty table displayed row 1 solely via `shownSet.add(0)`.   - `react-web/src/components/onefop/tables/VtRosterGrid.tsx:148-161`: Applied identical slot 0 retention logic.
- **Tests & Result:**
  - Added unit test in `react-web/src/components/onefop/tables/VtProgressiveRowGrid.test.tsx` verifying that clicking "Add" on an empty grid renders both row 1 and row 2 with slot 0 intact. Passed.
- **Findings Missed by Source Report:** In `VtRosterGrid.tsx`, a secondary bug where deleting rows left non-contiguous indices was also prevented by maintaining explicit slot retention.

- **Tests & Result:**

### Defect 9 — P2 · FE: Stale "Pending" header after endorsement
- **Status:** Fixed (`c4fc58b3`)
- **Cause:** Confirmed through live reproduction. Two factors combined:
  1. Clicking inside the native `<dialog>` modal fired browser window focus events. Because TanStack Query defaults to `refetchOnWindowFocus: true`, background refetches for `/diagnostic` and `/questionnaires/:id` were sent concurrently with `PATCH .../approve`.
  2. The concurrent `GET` read returned before the PATCH write committed in the DB, returning stale `PENDING_REVIEW` data. TanStack Query deduplicated in-flight requests, and `approveMutation.onSuccess` discarded the authoritative HTTP 200 response from `approveDossier` rather than updating query cache via `setQueryData`.
- **Changes:**
  - `react-web/src/app/admin/dossiers/[id]/page.tsx:411-460`: In `approveMutation.onSuccess`:
    - Cancelled any in-flight refetches for `["admin", "dossier", id]` and `["admin", "diagnostic", id]` (and `canonicalId`).
    - Wrote authoritative server response directly into query cache via `queryClient.setQueryData`.
    - Updated diagnostic cache to `axis1Endorsed: true`.
- **Tests & Result:**
  - End-to-end browser test with Playwright: endorsed submission, confirmed header status badge updated immediately from `"En instance"` to `"Visé"` and decision buttons disappeared without manual reload.
- **Findings Missed by Source Report:** The same potential race condition exists on `rejectMutation` and `correctionMutation` in the same file (flagged in Cross-cutting findings).

## 3. Cross-Cutting Findings

1. **Focus race on native `<dialog>` modals affecting Reject and Correction:**
   The reproduction of Defect 9 revealed that native `<dialog>` interactions trigger `window.onfocus`, causing TanStack Query to fire background refetches that race with pending mutations. In `dossiers/[id]/page.tsx`, `rejectMutation` and `correctionMutation` follow the same pattern as `approveMutation` previously did (calling `invalidateDossier()` without updating `setQueryData` or cancelling in-flight queries). While low risk in low-latency environments, they should adopt the same `setQueryData` pattern in a future cleanup pass.
2. **Derived-Value Hooks and Dirty Tracking:**
   `useVtDerivedCommune` was the only derived hook lacking dirty tracking. Other derived fields (e.g. table totals in `use-vt-fixed-row-totals.ts`) operate on mathematical sums of present values and do not overwrite manual text entry.
3. **Implicit-Slot Grids:**
   Both `VtProgressiveRowGrid.tsx` and `VtRosterGrid.tsx` shared the identical off-by-one slot 0 omission when adding rows from an empty state. Both grids have now been corrected.
4. **PII Across Export Endpoints:**
   Audited all export endpoints in `data-management.controller.ts`:
   - Main SPSS (.csv, .sav, syntax): Uses `CANONICAL_PII_EXCLUSIONS`. Verified that all 7 contact fields and 8.8 roster are excluded.
   - 8.8 Trainer Roster export: Restricted to `SUPER_ADMIN` and `ADMIN_ONEFOP`.
   - Contact export: Restricted to `SUPER_ADMIN` and `ADMIN_ONEFOP`.
   - Excel export: Audited; excludes raw password hashes and internal keys.
5. **401 Interception Consistency:**
   Previously, only client navigation routes checked tokens. Background polling queries lacked unauthenticated guards. The new `setOnUnauthorized` hook in `api-client.ts` centralizes session teardown across all API consumers.
6. **Generated Schema Flow:**
   `flutter test test/tools/export_onefop_schema_test.dart` outputs strictly to `assets/schemas/onefop.schema.json`. Frontend consumers read from `react-web/public/schemas/onefop.schema.json`. A build-time or git pre-commit sync script should be added so schema copying is automated.
